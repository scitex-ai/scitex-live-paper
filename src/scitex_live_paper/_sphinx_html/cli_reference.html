scitex-live-paper

scitex-live-paper (v0.5.4) — Emit a static live-paper site from an accepted bundle.

The M1 end-to-end loop: load an accepted manuscript bundle and emit a self-contained static site (viewer + claims + DAG + landing page + vendored assets) that opens straight from file:// — no server required. All claim / DAG semantics come from the bundle and, optionally, an evidence provider (see docs/evidence-provider-contract.md); this CLI never invents or validates fields.

Usage

scitex-live-paper [OPTIONS] [COMMAND] [ARGS]...

Options

--help-recursive

Show help for every subcommand, flattened.

--json

Emit machine-readable JSON (the command tree for the top level).

-V, --version

Show the version and exit.

Config resolution: –config PATH (explicit flag wins when the command accepts one) $SCITEX_LIVE_PAPER_CONFIG (environment override) <project>/.scitex/live-paper/config.yaml (project scope) ~/.scitex/live-paper/config.yaml (user scope)

export-review

Export the registered-claim review packet (JSON or text).

Builds the review packet (scitex-live-paper.review-packet v1) — every registered claim with its evidence state, reason, source, locator and minimal evidence graph, needs-inspection first — from an evidence report or an installed evidence provider. The same packet the rendered site is built from.

Usage

scitex-live-paper export-review [OPTIONS] [BUNDLE_PATH]

Options

--evidence-report <evidence_report>

Evidence report JSON a provider produced (contract scitex-live-paper.evidence-report v1).

--evidence-provider <evidence_provider>

Installed evidence provider (entry-point name, port ‘evidence’). Omit with –evidence-root to use the only installed one.

--evidence-root <evidence_root>

Project the evidence provider assesses, and where render reads the manuscript text (default: the bundle directory).

--format <fmt>
Options:

json | text

--out <out_path>

Write here instead of stdout.

--dry-run

Build the packet and report what would be written; write nothing.

-y, --yes

Overwrite an existing –out file without asking.

Arguments

BUNDLE_PATH

Optional argument

Examples: $ {prog} export-review –evidence-report report.json –out review.json Packet from a provider’s report file. $ {prog} export-review bundle/ –evidence-root proj/ –format text Plain-text packet from the installed provider.

hub-manifest

Print the scitex-hub workspace manifest as JSON.

Hub-side wrapper apps (e.g. apps/workspace/live_paper_app/manifest.json) can regenerate the file via redirect. The output is the v2.0.0 hub workspace UI shape — derived from scitex_live_paper.HUB_APP_MANIFEST. Default formatting is indented + sort_keys=True so successive runs produce stable, review-friendly diffs.

Usage

scitex-live-paper hub-manifest [OPTIONS]

Options

--label <label>

Override workspace tile title (default: HUB_APP_MANIFEST display_name).

--subtitle <subtitle>

Override short tagline (default: first sentence of description).

--schema-version <schema_version>

Hub manifest schema_version to declare.

Default:

'2.0.0'

--compact

Emit single-line JSON (default: indented + sorted for stable VCS diffs).

Examples: $ {prog} hub-manifest > manifest.json Regenerate the wrapper manifest. $ {prog} hub-manifest –compact | head -c 200 Single-line JSON for piping.

info

Print a one-screen sanity summary of a bundle.

Operator-facing pre-flight check: load the bundle (without rendering anything) and report claim count + status palette, paper_state stage + journal + DOI + pinned_commit, manuscript filename, whether the DAG is embedded, and the claims.json schema version. Pass –json for a stable machine-parseable summary.

Usage

scitex-live-paper info [OPTIONS] BUNDLE_PATH

Options

--json

Emit a JSON object instead of the human-readable summary.

Arguments

BUNDLE_PATH

Required argument

Examples: $ {prog} info bundle/ Human-readable sanity summary. $ {prog} info bundle/ –json | jq .paper_state.stage Machine-readable summary, staged field extraction.

install-shell-completion

Install the static completion drop-in script.

Writes the click-generated completion script once to ~/.scitex/live-paper/runtime/completion/ (cache-file pattern — no per-shell-start subprocess) and prints the installed path. Source that path from your shell rc to enable tab-completion. Idempotent — re-running never rewrites an identical script.

Proceed without confirmation (this command never prompts anyway).

Examples: $ {prog} install-shell-completion –shell bash Write the bash drop-in script and print its path. $ {prog} install-shell-completion –dry-run Print the target path without writing.

validate

Run a fuller pre-flight check than info.

On top of bundle.load()’s syntactic checks, validate runs claim integrity (duplicate claim_ids, known lifecycle statuses, hex-shaped source_hashes) and PaperState sanity (accepted/published stages need a pinned_commit). Reports every issue as <file>: <reason>; exits 0 on clean, non-zero (issue count) otherwise.

Usage

scitex-live-paper validate [OPTIONS] BUNDLE_PATH

Arguments

BUNDLE_PATH

Required argument

Examples: $ {prog} validate bundle/ Check before render or serve. $ {prog} validate bundle/; echo $? Count issues via the exit code.
