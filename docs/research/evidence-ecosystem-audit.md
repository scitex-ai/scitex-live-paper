# Evidence navigation across SciTeX packages

This source review supports the [claim popup design](../evidence-source-navigation.md). The links pin the implementation reviewed. The proposed integration work is described separately from current behavior.

## From production to the reader

| Surface | What it does today | What the popup needs from it |
| --- | --- | --- |
| FigRecipe | Reproduction records recipe, data, and override reads through its optional Clew integration. Saving records recipes, data outputs, and rendered images. It also owns Figz and its panel composition. | Use the existing lineage from the exact rendered figure. Keep FigRecipe's recipe or panel detail an optional action for a later release. A panel-specific claim needs an explicit panel identity and recorded association. [Reproducer](https://github.com/scitex-ai/figrecipe/blob/2b67bd5a/src/figrecipe/_reproducer/_core.py) · [Capture adapter](https://github.com/scitex-ai/figrecipe/blob/2b67bd5a/src/figrecipe/_serializer/_clew.py) · [Figure save](https://github.com/scitex-ai/figrecipe/blob/2b67bd5a/src/figrecipe/_api/_save.py) |
| SciTeX Session and IO | Session owns run lifecycle and writes a run config. IO exposes file-observation hooks. Clew registers with both via entry points and captures lineage without a dependency from their runtime code to Clew. | Reuse recorded run IDs, script hashes, and file identities. A parameter action should refer to a deliberately exposed, recorded parameter group. A run config can contain internal or sensitive values, so its existence alone does not make its contents a reader resource. [Session config](https://github.com/scitex-ai/scitex-session/blob/24d570d/src/scitex_session/_lifecycle/_config.py) · [IO observation](https://github.com/scitex-ai/scitex-io/blob/8986ea7/src/scitex_io/_observers/__init__.py) · [Clew registrations](https://github.com/scitex-ai/scitex-clew/blob/57ad743/pyproject.toml) |
| Clew | Writer uses its claim store. The Live Paper provider projects a slice back from the claim to a minimal graph. A process node in that projection currently keeps the session ID and omits the stored script path and hash. | Join the retained process node to its recorded run and expose the script and run resources. Use Clew's source types, color roles, and icon choices in both views. Treat a specific database query or extract as a database source when its origin is explicitly recorded. Storage implementation and filename type alone carry no such evidence. [Run fields](https://github.com/scitex-ai/scitex-clew/blob/57ad743/src/scitex_clew/_db/_schema.py) · [Graph projection](https://github.com/scitex-ai/scitex-clew/blob/57ad743/src/scitex_clew/_evidence_provider/_graph.py) |
| Writer | Registers claims through Clew and regenerates the derived `00_shared/claims.json` for the manuscript toolchain. Its editor uses SDK PDF rendering and the Live Paper compatibility export for Rich PDF. Its adapter translates Writer annotations and carries the editor's mutation policy. | Qualify the complete workflow using a Writer-compiled PDF. Bind PDF rectangles to the exact PDF revision and join them to evidence by claim ID. Recompilation invalidates old rectangles. If the Writer preview later shows evidence inline, mount the public Live Paper inspector on evidence regions while retaining Writer's annotation adapter. [Claim store adapter](https://github.com/scitex-ai/scitex-writer/blob/6ee7fb27/src/scitex_writer/_mcp/handlers/_claim_store.py) · [Editor adapter](https://github.com/scitex-ai/scitex-writer/blob/6ee7fb27/src/scitex_writer/_django/frontend/src/rich-pdf-adapter.ts) · [PDF anchor validation](../../src/scitex_live_paper/_django/handlers/_pdf_anchors.py) |
| Scholar | The saved-PDF view imports the compatibility provider and SDK factory. It supplies a read-only document port and tears down the viewer when another item is selected. This adapter supplies no evidence report or project resolver. | Ordinary library PDFs continue to be readable. An explicit, authorized association to a Live Paper bundle can enable evidence later. Bibliography or DOI links describe publications, and remain distinct from Clew's computational evidence. [Library reader](https://github.com/scitex-ai/scitex-scholar/blob/bf981a7/src/scitex_scholar/_django/static/scholar/js/library-pdf.js) |
| Live Paper and Hub | The Live Paper leaf renders evidence from a request-bound bundle or evidence snapshot. Hub uses SDK project access for its project-selected route and supplies the authorized bundle. The explicit working-directory route currently checks the caller's jail and has a different scope. | Enable new previews on the explicitly authorized project mount first. Resolve each resource against that project, claim, and evidence revision. For an exported snapshot or an explicit bundle path, keep graph navigation available and offer project resources only if the host supplies an authorized resolver for that bundle. [Evidence request](../../src/scitex_live_paper/_django/_evidence_request.py) · [Hub mount](https://github.com/scitex-ai/scitex-hub/blob/3d700fcd6/apps/workspace/live_paper_app/mount.py) |
| Agentic Journal | Supplies a paper-specific Live Paper resolver with its own publication and re-review state. | A publication mount can keep its exported evidence browsable. Code previews require a publication-scoped artifact grant or a separately authorized project. Add this as a compatibility check for public mounts. [Journal resolver](https://github.com/scitex-ai/scitex-agentic-journal/blob/874d8b1/src/scitex_agentic_journal/_hub_app_publisher/_resolver_adapter.py) |
| Rich PDF and SDK | SDK renders the PDF and supplies coordinate transforms. Rich PDF owns the component used for overlays, comments, and synchronized feeds. Live Paper copies the released provider assets for compatibility. The earlier UI package is archived in favor of SDK. | Add optional popover behavior in Rich PDF, using SDK page geometry. Consume the released component through the existing asset sync. Continue qualifying the Writer and Scholar import paths. [SDK exports](https://github.com/scitex-ai/scitex-sdk/blob/7df1114/src/scitex_sdk/package.json) · [Rich PDF provider](https://github.com/scitex-ai/scitex-rich-pdf/blob/v0.1.1/src/scitex_rich_pdf/frontend/pdf-provider.js) · [Compatibility assets](../rich-pdf-provider.md) |

For the figure test, render a figure through FigRecipe inside a recorded run, register that output as a Writer claim, then compile and bind the rectangle to the resulting PDF. The reader should resolve the claim to the recorded figure output, its producing run, and the matching script bytes. A second figure with a similar filename should resolve to its own claim. This exercises the boundary that a synthetic popover test cannot cover.

## Shared rules and enforcement

The [SciTeX Dev boundary convention](https://github.com/scitex-ai/scitex-dev/blob/78235625/src/scitex_dev/_skills/general/01_ecosystem/16_boundary-ports-and-producers.md) already covers the optional Clew provider and the public SDK and Rich PDF APIs. The [access primitive](https://github.com/scitex-ai/scitex-dev/blob/78235625/docs/adr/0014-access-primitive-v1.md) defines how hosts authorize content. Apply those conventions with the [reader integration rules](../rich-pdf-provider.md#reader-integration-rules). The domain-specific assertions belong in the [package-owned tests](https://github.com/scitex-ai/scitex-dev/blob/78235625/docs/rule-ownership.md).

| Owner | Check |
| --- | --- |
| Clew and Live Paper | Validate producer data against the exported contract. Exercise old reports, unknown presentation tokens, missing script hashes, and one process with more than one inspectable resource. Keep a native Clew view and the popup on the same source vocabulary. |
| Rich PDF | Exercise anchoring, pinning, focus, dismissal, geometry changes, and two simultaneous viewer instances. Verify the optional evidence hook can coexist with existing comments and feed behavior. |
| Live Paper and Hub | Verify that valid claims resolve only in their project and snapshot. Cover stale revisions, absent resources, a mismatched script hash, and unauthorized access, including from a publication or library mount. |
| Writer and Scholar | Run the released-wheel browser smoke checks through the current compatibility imports. Exercise Writer's annotation save and PDF recompile and Scholar's document switching and read-only mode. |

Keep code execution on the project's Console path. A preview request has read authority. Launching a job requires its own project authorization and an available isolated runtime. [Current Hub job API](https://github.com/scitex-ai/scitex-hub/blob/3d700fcd6/apps/workspace/console_app/job_api_views.py)
